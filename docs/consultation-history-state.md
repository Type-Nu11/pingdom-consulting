- 이번 범위는 상담 이력 상태·행동 분리다. #71의 전체 3단계나 상위 이슈 전체 완료를 의미하지 않는다.
- 기존 README·Vite 포트 변경은 보존하고 작업 대상에서 제외한다. 커밋·푸시·PR은 별도 승인 이후 진행한다.

## 상태 소유권

| 소유자 | 책임 |
| --- | --- |
| `features/consultation/hooks/useConsultationHistory.ts` | 이력 읽기, 목록/ref, 활성 ID, 고정/일반 목록, 메뉴·이름 편집·삭제 확인 대상, 이력 저장 갱신 |
| `AiHomePage` | 입력 초안·확정 단계, 복원 애니메이션 여부, AI/분석 요청과 취소, PDF 조회/다운로드 및 삭제 함수 연결 |
| 기존 `model`/`storage` | 타입·제목/표현/정렬 함수, v1 localStorage 읽기·쓰기 |
| 기존 분석 저장 모듈 | IndexedDB 보고서 읽기·저장·삭제 |

훅에 페이지의 현재 상담 필드를 `draft`로 전달한다. 페이지가 이력 목록이나 활성 ID를 별도 상태로 갖지 않으며 이력 훅도 단계별 입력 setter를 복제하지 않는다. 새 draft 객체가 렌더마다 만들어져도 기존 필드별 effect 의존성을 유지하여 메뉴/편집 렌더만으로 저장·수정시각 갱신이 반복되지 않도록 한다.

`onRestore`, `onReset`, `onDeleteReport` 콜백으로 단계/요청/보고서 책임을 연결한다. 훅은 React DOM 이벤트나 페이지 모듈을 가져오지 않으며 `stopPropagation`·폼 기본 전송 방지는 뷰에서 처리한다.

## 유지하는 동작

- 저장 키와 v1 JSON 형식, 저장소 실패 처리, 정렬 함수 및 PDF 키는 변경하지 않는다.
- 저장 이력은 최초 렌더에 읽지만 저장된 activeSessionId를 자동 선택하지 않는다.
- 새 질문을 보낼 때만 새 ID를 만든다. 새 상담은 기존 목록을 지우지 않고 활성 ID와 페이지의 상담 필드를 초기화한다.
- 같은 활성 상담 선택은 기존처럼 no-op이다. 다른 상담은 페이지에서 요청 취소·필드 복원 후 활성 ID를 바꾸고 메뉴를 닫는다.
- 이름 변경은 trim 후 빈 이름을 거부한다. 이름 변경·고정 자체로 createdAt/updatedAt을 새 값으로 바꾸지 않는다. 이후 상담 필드 변경 시 제목/고정/생성시각을 유지하며 현재 상담을 저장한다.
- 활성 상담 저장은 이전 페이지와 같이 정의된 현재 필드 스냅샷으로 갱신한다. storage 읽기 유틸의 알 수 없는 필드 보존과, 활성 상담 갱신 시 모든 임의 필드를 계속 보존하는 것은 구분한다.
- 삭제 요청은 확인 대상만 설정한다. 취소는 목록/PDF를 지우지 않고, 확인 대상이 없으면 확인 명령도 no-op이다.
- 비활성 상담 삭제는 현재 상담을 초기화하지 않는다. 활성 상담 삭제는 활성 ID를 해제하고 페이지 초기화 콜백을 실행한다. 보고서는 삭제 대상 ID로 기존 분석 저장 함수를 호출한다.
- PDF 삭제 실패의 기존 개발 로그 정책은 유지한다. 보고서 실패 복구 UX나 저장소 트랜잭션/롤백을 새로 구현하지 않는다.

## 계정 경계

현재 Router는 `AiHomePage`를 `user.id` key로 렌더한다. 훅은 이 계정별 페이지 수명 안에서 동작하며, 계정 전환 때 페이지·훅·편집/삭제 상태가 함께 재생성된다. 같은 훅 인스턴스에 다른 userId만 덮어 넣는 사용법을 추가하지 않는다. 추후 라우터 수명을 변경하면 계정 격리 검증도 함께 갱신해야 한다.
