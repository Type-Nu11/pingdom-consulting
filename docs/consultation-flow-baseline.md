## 실행

```sh
npm ci
npx playwright install chromium
npm test
npm run test:browser
npm run lint
npm run build
```

Playwright는 개발 의존성이다. 테스트는 별도 임시 Vite 서버(18471부터 빈 포트 선택), 독립 브라우저 컨텍스트 및 임시 캐시/스크린샷을 사용하고 종료 시 정리한다. 실행 로그의 `Artifacts` 경로에서 캡처를 확인한다. 사용자의 5173/5175 서버는 종료하거나 재사용하지 않는다.

실행 환경 PATH에 Node/npm이 없어 Codex 번들 Node와 pnpm을 통해 npm을 실행했다. 최초 명령 실패는 런타임 경로 문제이며 제품 테스트 실패가 아니다. npm 설치 시 감사 결과 20건(중간 9, 높음 11)이 보고되었으나 이번 범위에서 자동 수정하지 않았다. 기존 잠금 파일의 의존성 버전을 일괄 변경하지 않았고 Playwright와 playwright-core만 추가했다.

## 검증 설계

- 실제 Router, StrictMode, AiHomePage, 단계 패널, 인증 세션, localStorage 및 IndexedDB 보고서 저장 코드를 사용한다.
- 합성 계정 901/902, 합성 질문/주소/이메일/보고서만 사용한다. 각 화면 크기에서 새 컨텍스트를 사용하므로 사용자 브라우저 저장소에 접근하지 않는다.
- Axios adapter가 안내문·PDF·로그아웃 요청만 대체하며 미등록 API는 실패한다. 분석 과금·실제 이메일 전송·운영 데이터 삭제는 없다.
- 위치 검색/역지오코딩/지도 SDK 경계만 대역으로 바꾼다. 실제 지도 SDK의 렌더링·드래그·누수 검증은 이 테스트의 완료 주장에 포함하지 않는다.
- 외부 업무 네트워크는 차단한다. 웹폰트만 허용하며 실패 캡처에는 합성 데이터만 들어간다.
- 브라우저 시계로 타이핑·전환 타이머를 진행한다. 제품 타이머 상수나 UI 코드를 변경하지 않는다.

## 현재 동작 규칙

- 새 질문은 Enter로 제출하며 업종 → 위치 → 고객층 → 영업시간 → 요약 순서로 진행한다.
- 시작 시간을 고르면 종료 시간 선택기가 자동으로 열린다.
- 요약에서 업종 변경은 확정 위치·고객층·영업시간을 유지한다.
- 코드 확인: 위치 재확정은 고객층·영업시간·확정 추가 내용을 초기화한다. 고객층 재확정은 영업시간·확정 추가 내용을 초기화한다. 운영시간 재확정은 확정 추가 내용을 초기화한다. 이 초기화 조합 전체를 브라우저에서 검증한 것은 아니다.
- 분석은 계정 이메일을 읽기 전용으로 표시하고 동의가 없으면 요청 버튼을 비활성화한다. 실패 후 재시도 대화상자에서는 기존 동의 선택이 유지된다.
- 분석 처리 중 요청 버튼은 비활성화된다. 실패 시 단계 입력을 유지하고 재시도할 수 있다.
- 새로고침은 이력 목록만 복원한다. 저장된 activeSessionId가 있어도 활성 상담을 자동으로 열지 않는다. 상담을 선택하면 입력 및 IndexedDB PDF를 복원하고 분석 API를 다시 호출하지 않는다.
- 상담 메뉴는 hover 또는 focus-within에서 활성화된다. 테스트는 메뉴 버튼에 포커스를 주고 Enter로 열어 키보드 경로를 검사한다.
- 모바일은 사이드바가 숨겨져 이력/새 상담 접근 경로가 보이지 않는다. 모바일의 저장 상담 복원 검사는 잠시 데스크톱 폭에서 이력을 선택한 뒤 모바일 폭으로 돌아와 수행한다. 모바일 자체의 이력 접근 성공으로 해석하면 안 된다.
- 계정 변경은 Router의 계정 ID key로 화면을 재생성한다. 이전 계정 보고서의 늦은 완료가 새 계정 화면에 들어가지 않는지 검사한다.
- 손상되거나 차단된 localStorage는 빈 초기 화면으로 복구한다. 현재 코드는 저장 실패 안내를 제공하지 않으며, 손상 데이터의 원본 보존을 보장하지 않는다. 이번 변경은 이 정책을 개선하지 않는다.
