## 소유권과 연결

| 소유자 | 책임 |
| --- | --- |
| `useConsultationFlow` | 단계 초안/확정값 10개, 업종 표시/확정 가능 여부, 단계 확정/수정·초기화/복원 명령 |
| `useConsultationHistory` | 이력 목록·활성 ID·이름 변경/고정/삭제·계정별 v1 localStorage |
| `AiHomePage` | 질문/AI 안내, 요청 취소·보고서 오류/진행/PDF, 타이머, 폼 이벤트/배치, 두 훅 연결 |
| 기존 단계 패널 | 위치/고객층/시간/요약 입력 UI와 기존 동의·선택 동작 |

단계 훅은 API/저장소/타이머/DOM/페이지 모듈을 참조하지 않는다. 기존 `useState`
선언을 유지하고 새로운 reducer/전역 상태 라이브러리나 이중 상태를 만들지 않는다.
`ConsultationFlowState`는 기존 세션의 해당 10개 필드에 대한 `Pick` 타입이다.

페이지는 단계 훅의 필드를 기존 질문·AI 안내 값과 함께 이력 훅의 `draft`로 전달한다.
이력 훅의 필드별 effect 의존성과 저장 형식은 변경하지 않는다. 새 draft 객체 자체를
effect 의존성으로 추가하지 않아 메뉴/이름 편집 렌더가 현재 상담의 재저장을 유발하지 않는다.

새 상담·활성 상담 삭제·상담 복원에서는 페이지가 기존 요청 취소·보고서/입력창 정리
순서를 유지하면서 `resetFlow`/`restoreFlow`를 호출한다. `handleSummaryConfirm`은
기존 검증/동의/요청 흐름 안에서 `confirmSummary`를 호출하고 실패 시 요약 확정만 해제한다.
단계 수정 후 보고서 오류 초기화도 페이지의 기존 래퍼에 남긴다.

Router의 `user.id` key 아래에서 페이지와 두 훅이 함께 재생성된다. 단계 훅 자체에
계정 ID나 저장소를 추가하지 않으며 동일 인스턴스의 계정 ID만 바꿔 사용하는 API는 만들지 않는다.

## 유지한 전환 규칙

아래 이외 필드는 원래 값을 유지한다. 특히 입력 중인 `additionalDetails` 초안은
단계 수정만으로 지우지 않는다. 모든 단계 수정이 동일한 초기화 규칙을 쓰는 것은 아니다.

| 동작 | 변경/초기화 | 확정 추가 내용 |
| --- | --- | --- |
| 최초 업종 선택/확정 | 미선택/빈 기타 입력 차단, 기타 확정값만 trim, 확정 후 최초 선택 잠금 | 유지 |
| 일반 위치 확정 | 위치 교체, 고객층/영업시간 해제, 요약 확정 해제 | 비움 |
| 요약 위치 수정 | 위치 교체, 고객층/영업시간 해제, 요약 확정 해제 | 유지 |
| 고객층 확정 | 고객층 교체, 영업시간 해제, 요약 확정 해제 | 비움 |
| 고객층 수정 진입 | 고객층/영업시간 해제, 요약 확정 해제 | 유지 |
| 영업시간 확정 | 영업시간 교체, 요약 확정 해제 | 비움 |
| 영업시간 수정 진입 | 영업시간 해제, 요약 확정 해제 | 유지 |
| 요약 업종 수정 | 업종 코드/이름 교체, 요약 확정 해제; 위치/고객층/영업시간 유지 | 유지 |
| 요약 확정 | 추가 내용의 trim 값을 확정, 요약 확정 설정 | 초안에서 갱신 |
| 분석 실패 | 요약 확정만 해제; 보고서 오류/처리 상태는 페이지가 관리 | 유지 |

요약의 알 수 없는 업종명은 기존처럼 `OTHER`로 처리하며 최초 기타 입력과 달리
이 단계에서는 임의로 trim하지 않는다. `restoreFlow`도 기존 필드를 그대로 복원하며
새 저장 데이터 검증/마이그레이션·자동 활성 상담 복원 정책을 추가하지 않는다.
