# 상담 타이핑·단계 표시·전환 타이머 분리 — #71 3단계

기준: main `38c5c93496b74378c88d5ac5228623025ec0dcc8` (#78 병합).
브랜치: `refactor/consultation-animation-71`.

## 변경 범위와 상태 소유권

- `useTypewriter`가 기존 7개 안내의 텍스트·타이핑/완료 상태와 타이머 정리를
  소유한다. 표시 문구와 각 안내의 지연·속도·복원 플래그는 기존 페이지가 전달한다.
- `useCategorySequence`는 기존 업종 모델로 표시 순서를 만들고, 활성 인덱스와
  완료 상태를 관리한다. 220ms 대기, 38ms 글자 간격과 항목 사이 2틱을 유지한다.
  업종 확정 버튼 인덱스와 선택 처리 규칙은 그대로다.
- `useConversationTransition`은 기존 effect 위치에서 480ms 후 대기 질문을
  제출 상태에 넣고, 220ms 후에도 같은 대기 질문인 경우에만 정리한다.
  재실행/언마운트 시 두 타이머를 정리한다. 질문 상태는 이력 draft에 사용되므로
  페이지가 소유하고, 훅에는 기존 React setter를 직접 전달한다.
  새 effect 의존성 두 개는 안정적인 setter다. 질문·이력·첫 안내 요청 상태를
  새로 만들거나 순서를 바꾸지 않는다.
- 저장 상담 복원의 즉시 표시와 `prefers-reduced-motion`의 타이핑 생략을 유지한다.
  모션 줄이기 설정으로 질문 전환 타이머까지 생략하지는 않는다.
- 보고서 진행/완료 문구도 기존 인자로 타이핑하고, 완료 상태와 보고서 진행 타이머의
  연결은 그대로다. 레이아웃·CSS·스크롤·입력창 크기 조절·위치/지도·보고서 요청·
  API/저장 형식은 변경하지 않는다. README·Vite 로컬 수정은 제외한다.

- 고정된 #78 머지 소스에서 얻은 AST SHA-256으로 상수, 타이핑/카테고리 훅의
  기본 인자, 페이지의 8개 연결을 대조한다. 단위 검사 자체는 과거 Git 이력에
  의존하지 않는다. 변경 전 103개, 변경 후 106개 통과.
- 파일 분리와 기존 구조 검사 조정만 포함한 첫 커밋 예정 스냅샷에서도
  기존 단위 103개·lint·TypeScript 포함 빌드가 통과했다.
- 새 StrictMode Chromium 검사 6그룹은 480/220ms의 직전·직후, 초기화/교체,
  유니코드 글자 표시와 무관한 렌더, 업종 목록 타이밍/순서/복원, 계정 키 전환과
  언마운트의 타이머 정리, reduced-motion 동작을 확인한다.
- 기존 전체 상담 검사는 실제 페이지를 1920×1080, 1366×768, 390×844에서 열어
  질문부터 단계 표시·상담 확인·분석 동의·실패/재시도·다운로드·저장 복원을
  검증한다. 기존 브라우저 5종(전체 상담/안내/단계/이력/분석)은 변경 전후
